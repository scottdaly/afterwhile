# Teams meeting transcripts

M2 implementation, October 15, 2026. Synthetic fixtures only. **The extension has not yet been tried against live Teams.** The work-Mac trial must establish document/part identity, timestamp labels and protection markers before this is considered proven there.

## Established by the earlier structure-only probe

Recap in Teams web embeds `iframe#xplatIframe` on the organizer's SharePoint `/_layouts/15/xplatplugins.aspx`. Stream's `stream.aspx` shows the same transcript component top-level. Register the script with `allFrames: true` and request both Teams and SharePoint hosts only when the person enables Teams. Injection into already open matching tabs also uses all frames. Arbitrary SharePoint pages are ignored by the script.

Root `#OneTranscript`; scroll container `#scrollToTargetTargetedFocusZone`; rows `[id^='sub-entry-'][role='listitem']`; `aria-posinset` and `aria-setsize`; speech `[class*='entryText-']`; events `[class*='eventText-']`; speaker/time on the closest `[id^='entry-'][role='group']` aria-label. About 44 rows were drawn together in the probe. Several transcript parts can restart both positions and offsets. The earlier probe does not establish current production markup on other accounts.

## Identity: trial required

Only page addresses, rendered Stream links and selected transcript controls are read. There is no page-state, React-state, storage, network, token or API inspection.

The provisional address contract recognizes `id`, `docId`, `sourcedoc`, or the pair `driveId`/`itemId` in SharePoint page URLs. A Teams page can instead supply a single unambiguous rendered Stream link. Canonical identity is the host plus file locator; a selected transcript option's `value`, selected tab/option's `data-transcript-id`, or the page's `transcriptId` supplies the part key. Both Recap and Stream require an explicit selected-control or URL part key; no implicit single-part fallback is allowed. Their multi-part picker is unverified. **These URL/selected-control contracts are synthetic assumptions, not probe findings.** If Recap changes parts without changing one of these locators, capture must stay off until a structure-only probe establishes a stable key; do not invent a part index from row counts or offsets.

The first 128 bits of SHA-256 of each canonical document and part key makes ids opaque. Recap/Stream dedupe only if they expose the same canonical file and part locators; aliases cannot be guessed or resolved with an API. Missing/ambiguous identity stops capture. Distinct document ids are never merged just because the text matches. A row id is `<source>:line:<position>`. The source URL is a sanitized page link preserving the recognized file-locator parameter name and explicit transcriptId; following it round-trips the same part. It excludes session/download parameters. Its address can still contain private organizational information, so never print real source URLs in trial reports.

Selected-control labels are used only as the local source title. The current popup lists **observed parts**, not an assertion that every meeting part was discovered. The extension never clicks the part switcher. The person opens each part. A changed total stops the current reader. The worker persists that incompatibility across reloads, and the helper independently prevents complete coverage if saved positions exceed the extent or the recorded extent changes. The invalid flag survives until the person forgets the part, checks identity and captures again.

## Extraction and time

Each pass copies its identity, labels and rendered text synchronously before hashing, so a part switch during hashing cannot mix records and identity. Hidden roots/rows and hidden descendants are excluded using ancestor attributes, computed CSS and browser geometry; offscreen rows that are still drawn in the virtualized DOM can be read. The content script rejects a DOM generation change before submission. Each pass is atomic: malformed positions/totals, duplicate positions, missing text, ambiguous speech/event kind, or an unparseable label stops the whole pass. Empty shells wait. Missing transcript root outside a transcript leaves that page alone. No text is saved when a pass fails. No deletion is inferred from virtualized rows.

The provisional label parser supports a speaker followed by (or after) `mm:ss` or `h:mm:ss`. Localized word-based times are unverified and fail closed. Events are their own kind, with a null author and an offset. Speech requires a speaker. Event wording stays as displayed.

Meeting dates are not established by this component. `occurredAt` is explicitly first-capture time, with `fields.timeBasis` stating that the meeting date is unknown. Authoritative transcript time is `fields.offsetSeconds` / `fields.offset`. Database revisions preserve first-capture time. Markdown uses the capture day and orders by position, with speaker/event and relative offset; MCP also labels this limitation. Date filters therefore operate on capture time for Teams, not on meeting date.

## Reveal reading and exact coverage

Visible rows are queued immediately. Scrolling waits for 30 seconds without trusted input in a visible tab; input anywhere in Teams' outer page or its frames is shared through the worker. Hidden tabs may begin immediately. No synthetic mouse/key events are sent. Steps are at most half the container height, separated by the shared reader pause (usually 0.5–2.5 seconds, sometimes longer). It first walks toward the start from the current position, then down. Only one Teams frame across all tabs owns the scroll lock, with a short lease so an unloaded frame cannot hold it forever.

Drawn ids, not just scrollTop, establish progress. A hidden moved-but-undrawn list waits for visibility and idle. A visible list with three unchanged paints stops for the day. Returning to the tab starts the idle grace period. Original scrollTop is restored when idle if the person has not superseded it; shutdown of a stale extension script never moves the view. Fixed-height transcript rows and a stable scroll extent are assumed for pixel restoration and need live validation.

Coverage uses unique **database-saved** positions 1..setsize; only no gaps is complete. The helper recomputes it after ingest and on coverage updates. Queued rows cannot prove completeness. Coverage snapshots persist alongside the record queue and replay after helper/worker interruption. The popup uses native acknowledgements, not visit counts, and only says Complete once saved coverage confirms it. Forget turns Teams capture off, resets reader caches and invalidates old in-flight generations; re-enabling permits fresh capture. Navigation and tab removal invalidate tab-specific popup state. Completeness is per part, never per whole meeting. Unopened parts remain unknown.

## Restrictions and stopping

Never download a transcript file, read `temporaryDownloadUrl`, call Graph/SharePoint APIs, reuse tokens, or inspect hidden app state. Only the displayed component and its rendered navigation/control metadata are used. Download-disabled alone does not prohibit reading displayed rows; an explicit copy block or sensitivity label does.

Provisional protection markers include `data-copy-blocked`, `data-copy-allowed`, `data-sensitivity-label`, sensitivity-label class/aria-label markers, and rendered alert text about copying, confidentiality or restricted access. Sign-in, CAPTCHA and any unrecognized visible page alert/status notice pause Teams for the rest of the local day. Copy/sensitivity notices outside transcript speech also stop capture. **Protection selectors and localized warnings are unverified.** Stop the trial on any visible copy restriction or label that isn't detected. Some restrictions may live only in the outer Recap page: every matching frame scans its own displayed warnings, child frames wait until the outer page has passed its protection check, and a detected block pauses the whole connection. A synchronous restriction barrier is raised as soon as the parent message arrives, before serialized queue processing. Restriction state, a durable discard cutoff and the queue purge persist together; startup removes abandoned pre-cutoff rows even after the pause expires. The worker checks that barrier and shared restriction/pause/reset/navigation state before accepting records and again after persisting the queue, before any helper write. Absence of a recognized marker is not proof of permission. Employers may disallow copying or sharing with AI regardless of the UI.

## Trial checklist

Check Recap and Stream, file/part identity agreement (without printing locators), several reveal steps, exact setsize coverage, events, a second part if available, hidden-tab drawing, trusted input in parent/frame, safe restoration, reload idempotence, helper interruption/replay, popup counts, Markdown structure and actual MCP sources/search/recent/get/coverage. For MCP trials suppress record text from tool output and report only counts/booleans. Check a labelled or copy-blocked example only if already legitimately available; do not change protections to create one. Capture failures need structure-only evidence and a new synthetic fixture, never a real transcript or screenshot in the public repository.
